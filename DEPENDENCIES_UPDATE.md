## Стратегия обновления

Применена консервативная стратегия обновления:
- Обновлены только **minor** и **patch** версии
- **Major** версии оставлены без изменений для обеспечения совместимости
- React остался на версии **18.x** (React 19 не совместим с Gatsby 5)
- styled-components остался на версии **5.x** (версия 6 требует миграции)

## Уязвимости безопасности

### Текущее состояние

После обновления в проекте остаётся **23 уязвимости**:
- 18 низкой серьезности (low)
- 2 средней серьезности (moderate)
- 3 высокой серьезности (high)

### Важное замечание

Все обнаруженные уязвимости связаны с **транзитивными зависимостями** Gatsby и влияют только на **dev-окружение**:

1. **@parcel/reporter-dev-server** - используется только в режиме разработки
2. **cookie, body-parser, qs** - серверные пакеты для dev-сервера
3. **tmp, inquirer** - CLI инструменты

**Для production сборки эти уязвимости не критичны**, так как:
- Финальная сборка - это статические HTML/CSS/JS файлы
- Уязвимые пакеты не попадают в production bundle
- Сайт не использует Node.js сервер в продакшене

### Почему не применяем `npm audit fix --force`

Команда `npm audit fix --force` предлагает установить **Gatsby 3.3.1**, что:
- Является **breaking change** (откат с версии 5 на 3)
- Сломает весь проект
- Потребует полной переработки кода

### Рекомендации

1. **Для локальной разработки**: риски минимальны, так как dev-сервер запускается только на localhost
2. **Для CI/CD**: уязвимости не влияют на финальную сборку
3. **Мониторинг**: следить за обновлениями Gatsby, которые исправят уязвимости в транзитивных зависимостях
